Add `recoverAt(p, anchors)` returning `Parser(?T)` — error recovery / synchronization on a tuple of anchors. On `p` success: returns `Some(value)`. On `p` failure: scan forward from where `p` left off, trying every anchor at each position; the first to succeed wins, returning `null` with the cursor at the recovery point (anchor itself not consumed — caller chains `.skip(anchor)` to consume). Hit EOF without any anchor matching → `p`'s original `ParseError` propagates.

Anchors are passed as a comptime tuple (like `sequenceOf`) — each can be any `Parser(T)` regardless of `T`, so `char(';')`, `endOfInput()`, `whitespace1()`, etc. coexist naturally. The slice form (`[]const Parser(void)`) was rejected because forcing every anchor to wrap to void would create constant friction.

Compile-time error if `anchors` is empty. Doc comment notes the perf characteristic (O(N*A) anchor attempts).
