Fix critical bug: backtracking combinators (`choice`, `Parser(T).lookAhead`, `possibly`, `recoverAt`) saved `state.index` but not `state.bit_offset`, silently corrupting the bit cursor when bit parsers were used inside any of them. All four now save/restore both fields. Regression tests added — bit parser inside each combinator must read the same bits whether or not a prior alternative/peek/possibly/recovery touched the bit_offset. Surfaced by the pre-v1.0 code-quality audit.

Also: doc clarification on `stringLit` (always allocates, even unescaped strings — no zero-alloc fast path) and `keyword` (UTF-8 byte-boundary caveat — multi-byte codepoints aren't recognised by the ASCII-only continuation check).
